## Three things land outside lane L's own files

1. **`flake.nix` + `scripts/bin/cargo-xtask` +
   `scripts/check-dev-shell-tools.sh`.** `cargo xtask <verb>` was written in
   178 places and ran nowhere. No cargo alias can fix it: `[build] target =
   "wasm32-unknown-unknown"` makes the alias build a host tool for wasm and
   `getrandom` refuses; cargo offers no portable override from inside an alias
   (an array will not merge into a string, an empty string is rejected), and a
   hardcoded triple breaks CI. So it is a shell shim plus a PATH prepend
   mirroring the existing `sdk/bin` one, plus a check that fails if it
   un-wires. **Additive** — every previously-working invocation still works.

2. **`crates/fork-codec`.** Finishes the KFRR removal `b653ac7e7` started.
   Deletes `decode_reference_recipes` (a `pub use` from `lib.rs`, so this is a
   crate API change), its result type, the wire constants, ~500 lines of tests
   and one committed fixture; `reference_recipes.rs` goes 1,019 → 99 lines.
   The node TYPES stay — `ReferenceRecipeNode` is used in seven modules.

3. **`crates/host-native/fixtures`.** The 43 committed `.wasm` are gone; they
   are built from tracked sources and the tests run the producer themselves.
   **This changes provisioning: `cargo test -p host-native` now needs the dev
   shell plus BOTH `sysroot` and `sysroot64`.** Cold ~77s, warm ~1s. CI runs
   no `cargo test`, so CI is unaffected. A developer without the wasm64
   sysroot gets a loud error naming `scripts/build-musl.sh --arch wasm64posix`.

`Cargo.lock` moves 6 lines and adds no packages — `wasmparser` was already in
the graph and becomes a `host-native` dev-dependency.

## What is closed, and what is not

* **L3, L4, L5** — complete.
* **L-D4, epoch half — CLOSED.** `guest_module_for_this_epoch` refuses a guest
  declaring a different ABI epoch at all three compile sites and lets a
  pre-marker binary through, matching `host/src/process-lifecycle.ts`.
* **L-D4, import half — PINNED, not closed.** `spawn_guest_thread` trap-stubs
  any `kernel.*` import it cannot find by NAME, so a renamed or dropped import
  instantiates fine and traps only if its path runs. Six of sixteen are
  stubbed deliberately, so making unknown imports an error would refuse every
  fixture. Both sets are pinned; a seventeenth import or seventh stub fails
  and names itself. Closing it properly means defining those six as named
  traps first — a design decision, not a patch.
* **Channel-LAYOUT drift is caught by neither host.** It is the only kind of
  staleness these fixtures actually exhibited.
* **`dylink-archive-wasm32.bin` stays committed and cannot be regenerated by
  anything** — its writer and its generator were both deleted with the
  TypeScript `ld.so`. Sixteen committed binaries remain, twelve of them live
  cross-language guards.
* **Delegated to lane F:** nothing re-runs the twelve fixture generators, so a
  fixture can silently stop representing what TypeScript writes. The question
  is not how to keep them fresh — that would guard code lane F is deleting —
  but which survive the Rust-first cutover and what produces the survivors.
* **Open for the maintainer:** the rebaseline to 4,575; the ~2,400 unaudited
  TypeScript lines; the other lanes' three suppressed measures and three
  failing packages; fifteen commit subjects from 2026-09-13 running 73–77
  columns.
